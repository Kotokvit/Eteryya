# P³ Engine — План Доноров

**Принцип**: Убивать и жрать и рождать новое.  
Не зависеть. Не клонировать. Взять лучшее — понять — переписать под своё.  
Компилятор без понимания бесполезен. Код без понимания — мусор, даже если компилируется чисто.

**Цель**: P³-движок на Zig с нашей проективной математикой (PGL(4,ℝ), Фубини-Штуди, идемпотенты)  
**Уже есть**: poler-os (Zig, крипто + точные расчёты) — это не донор, это НАШ код.

## Донор #1: zmath (zig-gamedev/zmath)

**URL**: https://github.com/zig-gamedev/zmath  
**Что это**: SIMD-математическая библиотека, ~140 процедур, x86_64 + AArch64  
**Лицензия**: MIT

### Мясо (берём)

| Что | Почему | Объём |
|---|---|---|
| SIMD F32x4 / F32x8 / F32x16 | Базовый тип для точек в P³: HomVec4 = f32x4 | ~200 строк ядра |
| `sin`, `cos`, `atan` SIMD | Фубини-Штуди = arccos(inner_product) | ~100 строк |
| `dot3`, `dot4`, `cross3` | Скалярное произведение в гильбертовом пространстве | ~50 строк |
| `load`/`store` для SIMD | Загрузка/сохранение точек из памяти | ~30 строк |
| `normalize3`, `normalize4` | Дегомогенизация P³ → R³ = нормализация | ~20 строк |
| Матричные операции `mul` | PGL(4,ℝ) = 4×4 матрицы × векторы | ~100 строк |

### Мусор (выкидываем)

| Что | Почему |
|---|---|
| `lookToLh`, `lookToRh`, `perspectiveFovLh` | Евклидовы проекции — у нас P³-проекции |
| `rotationX/Y/Z`, `rotationAxis` | Евклидовы вращения — у нас PGL(4,ℝ)-действия |
| Row-major convention | Нам нужен канонический column-major для PGL(4,ℝ) |
| F32 только | Нам нужны и f64 для точных вычислений Фубини-Штуди |

### Что переписываем

1. **zmath → p3_math.zig**: SIMD ядро оставляем, но меняем convention на column-major
2. Добавляем `f64x4` для точных вычислений (Фубини-Штуди требует двойную точность)
3. Добавляем `HomVec4` тип с гомогенной координатой w
4. Добавляем `PGL4` тип — 4×4 матрица с det ≠ 0 guarantee (comptime check)

## Донор #2: zm (griush/zm)

**URL**: https://github.com/griush/zm  
**Что это**: SIMD math, Vec/Mat любого размера, кроссплатформенный  
**Лицензия**: MIT

### Мясо (берём)

| Что | Почему | Объём |
|---|---|---|
| `Vec(n, T)` comptime-конструктор | Vec(4, f64) = HomVec4 — прямо наша точка! | ~100 строк |
| `Matrix` любой размерности | Matrix(4, 4, f64) = наш PGL(4,ℝ) | ~150 строк |
| `add`, `sub`, `mul` для Vec/Matrix | Базовая алгебра | ~80 строк |
| `dot`, `cross` | Скалярное/векторное произведение | ~40 строк |
| `normalize` | Дегомогенизация | ~20 строк |

### Мусор (выкидываем)

| Что | Почему |
|---|---|
| `AABB` (bounding box) | Евклидова концепция — в P³ нет AABB |
| `Ray` | Евклидов луч — у нас проективная прямая |
| `Quaternion` | Нужен только если делаем SO(3) вращения — у нас PGL(4,ℝ) |

### Что переписываем

1. **zm Vec → p3_homvec.zig**: Vec(4, f64) с семантикой однородных координат [x:y:z:w]
2. **zm Matrix → p3_pgl.zig**: Matrix(4, 4, f64) с гарантией det ≠ 0 и PGL-действием
3. Добавляем `fsDistance(p1, p2)` = arccos(|⟨p1,p2⟩|) — Фубини-Штуди
4. Добавляем `antipodalCheck(p1, p2)` — проверка Z/2Z (p ≈ −p)

## Донор #3: Mach Engine (hexops/mach)

**URL**: https://github.com/hexops/mach  
**Что это**: Полный движок: WebGPU, compute shaders, модульный, кроссплатформенный  
**Лицензия**: MIT/Apache

### Мясо (берём)

| Что | Почему | Объём |
|---|---|---|
| `sysgpu` — GPU абстракция | WebGPU + Vulkan + Metal + D3D12 — кроссплатформенный GPU | ~5000 строк (ядро) |
| Compute shader pipeline | PGL(4,ℝ) × 10⁶ точек на GPU | ~300 строк API |
| `shader.zig` — шейдерная компиляция | WGSL шейдеры для P³-рендера | ~200 строк |
| `gpu_allocator.zig` | GPU-память под точки/матрицы | ~100 строк |
| Mach `math/` (vec, mat, quat) | Дублирует zmath/zm — берём лучшее из обоих | ~300 строк |

### Мусор (выкидываем)

| Что | Почему |
|---|---|
| `Audio`, `Opus` | Не нужно для P³-движка |
| `Core`, `win32` | Платформенные костыли — у нас свой entrypoint |
| `editor/` | Редактор Mach — нам нужен свой |
| `examples/` | Евклидовы примеры — не наша геометрия |
| `graph.zig` | ECS-подобная система — если нужна, берём отдельно |

### Что переписываем

1. **Mach sysgpu → p3_gpu.zig**: GPU-абстракция без Mach-зависимости
2. Пишем **P³ compute shader** на WGSL: transform(point, PGL4_matrix)
3. Пишем **P³ vertex shader**: дегомогенизация P³ → R³ на GPU
4. Пишем **P³ fragment shader**: Фубини-Штуди distance-based shading

## Порядок пожирания

```
Фаза 1: МАТЕМАТИКА (ядро)
  Донор #2 (zm) → p3_homvec.zig + p3_pgl.zig
  Донор #1 (zmath) → p3_math.zig (SIMD ядро)
  ↓
  Результат: p3_kernel.zig (полная замена p3_kernel.py)

Фаза 2: GPU (compute)
  Донор #3 (Mach sysgpu) → p3_gpu.zig
  ↓
  Результат: PGL(4,ℝ) на GPU через compute shaders

Фаза 3: РЕНДЕР (визуализация)
  Донор #5 (raylib) → p3_raylib_bridge.zig (прототип)
  Донор #3 (Mach) → p3_renderer.zig (production)
  ↓
  Результат: 3D-рендер с P³-геометрией

Фаза 4: ФИЗИКА (динамика)
  Донор #7 (Astrodynamics) → RK4/RK45 интеграторы
  Донор #6 (zphys) → структура проекта
  ↓
  Результат: p3_geodesic.zig + p3_dynamics.zig

Фаза 5: UI/DEBUG
  Донор #4 (zgui, ztracy) → временно как есть
  ↓
  Результат: рабочий визуализатор на Zig
```

## Правила пожирания

1. **Понять перед тем как брать** — прочитать каждую строку, понять зачем она, решить наша ли это математика
2. **Переписать под своё авторство** — не copy-paste, а написать заново с нашим пониманием
3. **Тестировать на нашей математике** — не на треугольниках из примеров, а на Фубини-Штуди, на PGL(4,ℝ), на идемпотентах
4. **comptime где возможно** — D ∈ {128,256,512} на компиляции, не в runtime
5. **f64 для науки, f32 для рендера** — точность Фубини-Штуди требует double
6. **Ни одной зависимости в runtime** — всё либо наше, либо C-ABI через @cImport
